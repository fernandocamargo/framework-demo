Fragments, Not Plumbing
A React framework · November 2026

Agents write fragments. The framework writes the plumbing.

A screen is a folder of small files, each declaring one thing. Fetching, caching, invalidation, tracking, error reporting and types come from the framework, the same way every time.

// The editor's flow, for a product the address names (`edit`) or a new one (`create`).
//
// The rules it holds:
// - a save with problems in the form goes nowhere, and shows them;
// - closing with unsaved changes asks first;
// - a save refused because somebody else saved meanwhile is a conflict, not a failure: the
//   person keeps their changes and chooses whose version stays;
// - a failed save keeps the changes, to try again.

import { problems } from './form';

export const description = 'Edit a product, or write a new one, and save it.';

export const context = ({ route }) => ({
  /** Whether a save was tried: problems show from then on. */
  checked: false,
  creating: route.create,
  error: null as null | string,
  title: '',
  /** The version the person started from. A save says so, and is refused if the product has moved on. */
  version: 1,
});

// ---- Checks ----------------------------------------------------------------------------------

export const creating = ({ context }) => context.creating;
export const unsaved = ({ form }) => form.unsaved;
export const invalid = ({ form }) => problems(form.values).length > 0;
export const isConflict = ({ event }) => event.error instanceof Error && event.error.name === 'ConflictError';

// ---- Changes ---------------------------------------------------------------------------------

export const seedForm = ({ event, form }) => {
  form.seed(event.output);
  return { checked: false, error: null, title: event.output.title as string, version: event.output.version as number };
};
export const showProblems = () => ({ checked: true });
export const rememberError = ({ event }) => ({
  error: event.error instanceof Error ? event.error.message : String(event.error),
});
export const forgetError = () => ({ error: null });
export const close = ({ navigation }) => navigation.go({ create: false, edit: null });

// ---- What the services are given ---------------------------------------------------------------

export const productToRead = ({ route }) => route.edit ?? 0;
export const changesToSave = ({ context, form, route }) => ({
  changes: form.payload(),
  id: route.edit ?? 0,
  version: context.version,
});
/** The same changes, whatever the product's version: the person chose to keep theirs. */
export const changesToForce = ({ form, route }) => ({ changes: form.payload(), id: route.edit ?? 0 });
export const productToCreate = ({ form }) => form.payload();

// The chart is declared from what the person may do: a read-only editor has no `save` at all. When
// that changes (a sign-in, a session that ends), the framework declares it again and the flow keeps
// its place.
export default ({ acl, services }) => ({
  starting: {
    always: [{ guard: creating, target: 'editing' }, { target: 'loading' }],
  },
  loading: {
    description: 'Reading the product. Its values seed the form once.',
    invoke: {
      input: productToRead,
      onDone: { actions: seedForm, target: 'editing' },
      onError: { actions: rememberError, target: 'unavailable' },
      src: services.products.get,
    },
    on: { close: { actions: close } },
  },
  unavailable: {
    description: 'The product could not be read.',
    on: { close: { actions: close }, retry: 'loading' },
  },
  editing: {
    description: 'The person changes the fields.',
    on: {
      ...(acl.allowed && {
        save: [
          { actions: showProblems, guard: invalid },
          { guard: creating, target: 'creating' },
          { target: 'saving' },
        ],
      }),
      close: [{ guard: unsaved, target: 'confirmingDiscard' }, { actions: close }],
    },
  },
  confirmingDiscard: {
    description: 'There are unsaved changes. The person discards them or goes back to them.',
    on: { discard: { actions: close }, keepEditing: 'editing' },
  },
  saving: {
    description: 'The changes are sent, for the version the person started from.',
    entry: forgetError,
    invoke: {
      input: changesToSave,
      onDone: 'saved',
      onError: [
        { guard: isConflict, target: 'conflict' },
        { actions: rememberError, target: 'failed' },
      ],
      src: services.products.save,
    },
  },
  creating: {
    description: 'The new product is sent.',
    entry: forgetError,
    invoke: {
      input: productToCreate,
      onDone: 'saved',
      onError: { actions: rememberError, target: 'failed' },
      src: services.products.create,
    },
  },
  conflict: {
    description:
      'Somebody else saved this product meanwhile. The person keeps their changes or takes the newer version.',
    on: { close: { actions: close }, keepMine: 'overwriting', takeTheirs: 'loading' },
  },
  overwriting: {
    description: "The person's changes are saved over the newer version.",
    invoke: {
      input: changesToForce,
      onDone: 'saved',
      onError: { actions: rememberError, target: 'failed' },
      src: services.products.save,
    },
  },
  failed: {
    description: 'The save failed. The changes are still in the form.',
    on: {
      close: [{ guard: unsaved, target: 'confirmingDiscard' }, { actions: close }],
      edit: 'editing',
      retry: [{ guard: creating, target: 'creating' }, { target: 'saving' }],
    },
  },
  saved: {
    description: 'Saved. The lists that showed the product have read again; the editor closes.',
    entry: close,
  },
});

// The editor's fields: how a product becomes their values, how the values become the changes
// to save, and what is wrong with them. Pure functions; the framework keeps the values.

import type { Changes, Detailed } from '@/services/products/types';

export const seed = (product: Detailed | undefined) => ({
  brand: product?.brand ?? '',
  category: product?.category ?? '',
  description: product?.description ?? '',
  price: product?.price ?? Number.NaN,
  stock: product?.stock ?? 0,
  title: product?.title ?? '',
});

export type Values = ReturnType<typeof seed>;

export const payload = (values: Values): Changes => ({
  brand: values.brand.trim(),
  category: values.category,
  description: values.description.trim(),
  price: Math.round(values.price * 100) / 100,
  stock: Math.trunc(values.stock),
  title: values.title.trim(),
});

/** The fields whose values stop a save. Empty when nothing does. Each is worded by i18n.ts's `problems`. */
export const problems = (values: Values) => {
  const found: ('category' | 'price' | 'stock' | 'title')[] = [];
  if (!values.title.trim()) found.push('title');
  if (!values.category) found.push('category');
  if (!(values.price > 0)) found.push('price');
  if (!(values.stock >= 0)) found.push('stock');
  return found;
};

// flow itself with the services a test gives it. No React, no network.

import type { Detailed } from '@/services/products/types';
import { formOf, startFlow } from 'framework/testing';

import * as form from './form';
import * as editor from './state';

const product: Detailed = {
  brand: 'Tandem',
  category: 'audio',
  description: 'Two inputs.',
  id: 4,
  images: [],
  price: 167.99,
  rating: 4.2,
  stock: 64,
  thumbnail: '',
  title: 'Audio Interface',
  version: 3,
};
const conflict = Object.assign(new Error('Somebody else changed this product.'), { name: 'ConflictError' });

function editing(
  overrides: {
    create?: (input: unknown) => Promise<unknown>;
    creating?: boolean;
    save?: (input: unknown) => Promise<unknown>;
  } = {},
) {
  const fields = formOf(form);
  const go = vi.fn();
  const save = vi.fn(overrides.save ?? (async () => ({ id: 4, version: 4 })));
  const create = vi.fn(overrides.create ?? (async () => ({ id: 10_001 })));
  const flow = startFlow(editor, {
    form: fields,
    navigation: { go },
    route: { create: Boolean(overrides.creating), edit: overrides.creating ? null : 4 },
    services: { products: { create, get: async () => product, save } },
  });
  return { create, fields, flow, go, save };
}

test('the checks are plain functions of what they are given', () => {

  expect(form.problems({ ...form.seed(product), price: 0, title: ' ' })).toEqual(['title', 'price']);
});

components/catalogue/async.ts9 lines
// The catalogue waits for its page of products before it shows. The framework records what
// this read: the two services and these five route fields. So another filter, sort or page in
// the address is another read; a dialog opening is not; and a write that makes
// `products.search` stale (services/products/meta.ts) reads the page on screen again.
export default async ({ route, services }) => {
  const filters = { category: route.category, order: route.order, page: route.page, q: route.q, sort: route.sort };
  const [page, categories] = await Promise.all([services.products.search(filters), services.products.categories()]);
  return { categories, filters, page };
};

import { filtered, HOME, href } from '@/address';

export default ({ acl, async: { default: answer }, i18n }) => {
  const { categories, filters, page } = answer;
  const category = categories.find(({ slug }) => slug === filters.category)?.name ?? '';
  const narrowed = Boolean(filters.q || filters.category);
  return {
    bulkHref: href(filters, { bulk: true }),
    canChange: acl.allowed,
    categories,
    clearHref: narrowed ? href(HOME) : null,
    createHref: href(filters, { create: true }),
    empty: page.items.length === 0,
    emptyText: narrowed ? i18n.empty.narrowed : i18n.empty.none,
    filters,
    i18n,
    items: page.items,
    paging: {
      nextHref: page.page < page.pages ? filtered(filters, { page: page.page + 1 }) : null,
      previousHref: page.page > 1 ? filtered(filters, { page: page.page - 1 }) : null,
      shown: page.pages > 1,
      text: i18n.paging.page({ page: page.page, pages: page.pages }),
    },
    /** How many products, with what marks the count: `summary(count)`. */
    summary: (count: (chunks: ReactNode[]) => ReactNode) =>
      i18n.summary({
        category,
        count: page.total,
        filter: filters.q && category ? 'both' : filters.q ? 'q' : category ? 'category' : 'none',
        q: filters.q,
        total: count,
      }),
    total: page.total,
  };
};

// What the data layer needs to know about the catalogue's operations: which ones read, how
// long an answer that rarely changes stays good, what each write makes stale, and how some
// writes change what is shown before the server answers. By reference: rename an operation and
// this file follows, or fails to compile.
// A component that read one of these reads again when a write makes it stale. No component
// says so, and no component calls an invalidation.

import { update } from 'framework';

import type { Listed, Page } from './types';

/** A product as the overlay will keep it: changed here, one version on. What the server will answer, so nothing renders twice. */
const edited = <T extends Listed>(product: T, changes: Partial<Listed>): T => ({
  ...product,
  ...changes,
  local: product.local ?? 'edited',
  version: product.version + 1,
});

/** A list with one product changed, or the same list. */
const changed = (page: Page, id: number, changes: Partial<Listed>): Page =>
  page.items.some((item) => item.id === id)
    ? { ...page, items: page.items.map((item) => (item.id === id ? edited(item, changes) : item)) }
    : page;

// overlay the tabs share, once its change can be read there.

  categories: { freshFor: 5 * 60_000, reads: true },
  create: { invalidates: [products.search, products.inventory] },

  inventory: { follows: (stale) => local.changed(stale), reads: true },
  // A deletion leaves the list at once.
  remove: {
    invalidates: [products.search, products.get, products.inventory],
    optimistic: [

        page.items.some((item) => item.id === id)
          ? { ...page, items: page.items.filter((item) => item.id !== id), total: page.total - 1 }
          : page,
      ),
    ],
  },
  reset: { invalidates: [products.search, products.get, products.inventory] },
  reviews: { freshFor: 60_000, reads: true },
  // A save shows at once in the list and in the product's dialog; a conflict or a failure takes it out.
  save: {
    invalidates: [products.search, products.get, products.inventory],

      update(products.search, (page, { changes, id }) => changed(page, id, changes)),
      update(products.get, (product, { changes, id }) => (product.id === id ? edited(product, changes) : product)),

// The catalogue's operations. Reads ask DummyJSON and lay the local overlay over the answer.
// Writes go to DummyJSON first, signed in, so the network and the session are exercised for
// real; DummyJSON echoes them and keeps nothing, so the overlay keeps them (clients/local).
// The services' meta.ts says which of these read and what each write makes stale.

import { isLocal } from '@/clients/local';

import { laid, layPage, PAGE_SIZE } from './overlay';
import type { Category, Changes, Detailed, Listed, Local, Page, Product, Query, Review } from './types';

const LISTED = 'title,description,category,brand,price,stock,rating,thumbnail';

type Listing = { products: Omit<Listed, keyof Local>[]; total: number };

class NotFoundError extends Error {
  override name = 'NotFoundError';
}

/** A page of products, filtered and sorted as the query says. */
export const search =
  ({ clients: { api, local } }) =>
  async (query: Query): Promise<Page> => {
    const skip = (query.page - 1) * PAGE_SIZE;
    const sorting = { order: query.order, select: LISTED, sortBy: query.sort };
    // DummyJSON filters by a category or by text, not both: within a category, the text is
    // matched here, over the whole category.
    const remote = query.category
      ? api
          .get<Listing>(`/products/category/${encodeURIComponent(query.category)}`, { query: { ...sorting, limit: 0 } })
          .then(({ products }) => {
            const found = products.filter(
              (product) =>
                !query.q || `${product.title} ${product.description}`.toLowerCase().includes(query.q.toLowerCase()),
            );
            return { items: found.slice(skip, skip + PAGE_SIZE), total: found.length };
          })
      : api
          .get<Listing>(query.q ? '/products/search' : '/products', {
            query: { ...sorting, limit: PAGE_SIZE, q: query.q, skip },
          })
          .then(({ products, total }) => ({ items: products, total }));
    const [answer, overlay] = await Promise.all([remote, local.read()]);
    return layPage(answer, overlay, query, PAGE_SIZE);
  };

/** One product, with its pictures. */
export const get =
  ({ clients: { api, local } }) =>
  async (id: number): Promise<Detailed> => {
    const overlay = await local.read();
    if (overlay.removed.includes(id)) throw new NotFoundError('This product was deleted.');
    if (isLocal(id)) {
      const created = overlay.created.find((product) => product.id === id);
      if (!created) throw new NotFoundError('This product no longer exists.');
      const { reviews: _, ...product } = created;
      return laid(product, overlay, true);
    }
    return laid(
      await api.get<Omit<Product, 'reviews'>>(`/products/${id}`, { query: { select: `${LISTED},images` } }),
      overlay,
    );
  };

/** A product's reviews. A product created here has none. */
export const reviews =
  ({ clients: { api } }) =>
  async (id: number): Promise<Review[]> =>
    isLocal(id)
      ? []
      : (await api.get<{ reviews: Review[] }>(`/products/${id}`, { query: { select: 'reviews' } })).reviews;

/** Every product, for the report: the whole list the API keeps, with this browser's overlay laid over it. */
export const inventory =
  ({ clients: { api, local } }) =>
  async (): Promise<Listed[]> => {
    const [{ products }, overlay] = await Promise.all([
      api.get<Listing>('/products', { query: { limit: 0, select: LISTED } }),
      local.read(),
    ]);
    const removed = new Set(overlay.removed);
    return [
      ...overlay.created.map(({ images: _, reviews: __, ...product }) => laid(product, overlay, true)),
      ...products.filter((product) => !removed.has(product.id)).map((product) => laid(product, overlay)),
    ];
  };

export const categories =
  ({ clients: { api } }) =>
  () =>

/**
 * Saves a person's changes to the version of the product they started from. Rejects with a
 * `ConflictError` when the product has a newer version: somebody else saved meanwhile.
 */
export const save =
  ({ clients: { api, local } }) =>
  async ({
    changes,
    id,
    version,
  }: {
    changes: Partial<Changes>;
    id: number;
    version?: number;
  }): Promise<{ id: number; version: number }> => {
    // A product created here exists only here: the API is still asked who is signed in.
    if (isLocal(id)) await api.get('/auth/me', { auth: true });
    else await api.put(`/auth/products/${id}`, changes, { auth: true });
    return { id, version: await local.edit(id, changes, version) };
  };

export const create =
  ({ clients: { api, local } }) =>
  async (changes: Changes): Promise<Product> => {
    await api.post('/auth/products/add', changes, { auth: true });
    return local.create({ ...changes, images: [], rating: 0, reviews: [], thumbnail: '' });
  };

/**
 * Sets a product's stock, whatever its version: a count taken in the stockroom, not an edit of
 * what somebody else saved. Each press of a row's buttons sends one, with the count the row shows.

export const setStock =

  async (id: number): Promise<void> => {
    if (isLocal(id)) await api.get('/auth/me', { auth: true });
    else await api.delete(`/auth/products/${id}`, { auth: true });

// OpenFeature's in-memory provider serves these same flags (index.ts), so nothing else changes
// when it does: the provider is the one line that changes.
//
// Each flag has its values, the value the app falls back on when the provider cannot answer, and
// the ways it can be served: who gets which value. One way is served at a time; the network lab
// chooses another, as GrowthBook's dashboard would.

import type { Acl, Flags } from 'framework';

/** Who is asking, as the provider targets them: by id, and by the role the backend gives them. */

  fallback: Value;
  /** The flag's key at the provider. */
  key: string;
  /** The way served until the lab chooses another. */
  served: string;
  variants: Record<string, Value>;
  /** Each way the flag can be served: the variant each person gets. */
  ways: Record<string, (who: Targeting) => string>;
};

How it works

The build writes what the screen leaves out

React libraries usually work while the app runs. This one also works before: the build reads every file as a tree of meaning, as a compiler does, and edits the tree before the browser sees it.

  1. Vite plugin

    Reads the folders

    File names are the wiring. A folder with a render file becomes a component. Every service and client is found and connected.

  2. AST rewrite · compile-time macro

    Rewrites the code

    Every on… handler is wrapped to report where it was written. The file people read stays as they wrote it.

  3. TypeScript plugin

    Teaches the editor

    The editor sees what the build adds, so autocomplete, hovers and errors work as if everything were written by hand.

  4. Convention check

    Names the mistakes

    A misnamed or misplaced file fails the type check, with its path and the rule it breaks.

Has this been done before?

The approach, yes. For ten years, frameworks have been moving into the build and rewriting code with macros. That is what makes this a safe bet.

Svelte2016
The framework is a compiler and mostly disappears before the app runs. Its launch post: “Frameworks without the framework”.
Vue and Nuxt
Call their build-time functions macros, such as defineProps and definePageMeta. Their editor tooling types what the build rewrites.
Vite-plugin frameworks
SvelteKit, React Router, TanStack Start and Qwik each ship as a Vite plugin, as this one does.
AngularGoogle
An architectural framework with a compiler: its decorators, such as @Injectable, are compiled away ahead of time.
RedwoodJSReact
The closest relative on React. A build plugin turns a cell’s exports (Loading, Failure, Success) into a component. Service files are wired by folder.
React CompilerMeta
Rewrites React code at build time. Stable since 2025.

What is new is how much the build carries, and how little the code shows. The layers, what each screen receives, what a save makes stale, what is tracked and where failures go all come from the build. No macro appears in the code: the folder and file names are the macros. We found no framework on React that goes this far.

Engineering principles

What the structure enforces

Separation of concerns

One file per concern. A flow change never touches markup.

Single source of truth

The flow lives in its chart. Cache rules live in meta.ts.

Don’t repeat yourself

Fetching, caching, tracking and reporting are written once, in the framework.

Convention over configuration

Folder and file names are the wiring. No registries.

Explicit over implicit

Flows are statecharts, not effects. Services are referenced, not named by strings.

Dependency injection

Screens receive services, clients and the selected account. They never import or build them.

Fail fast

Wrong names, events and fields are type errors before anything runs.

Observability by default

Every interaction is tracked and every failure reported, without code in the screen.

Testability

Checks and changes are pure functions. Services are swapped by injection.

Open for extension

A new concern is a new file beside the others. Existing files stay untouched.

Platform first

Native events, native CSS, the browser’s own APIs before libraries that imitate them.

Simplicity

Each file has one job a newcomer can name. Small enough to review in one sitting.
